# TenthMatrix website secrets (Vault, per environment)

TenthMatrix reads its runtime secrets from **Vault at `vault.workstation.co.uk`**
(KV v2 compat mount `kv`) through the **External Secrets Operator**, the same
pattern Workstation uses (`../workstation-website/devops/VAULT-SECRETS.md`).
Every environment has its own path at the **root of the mount**, prefixed by
the namespace slug, so int / test / acc / prod secrets are distinct:

```
Vault kv mount (vault.workstation.co.uk)     ESO (ClusterSecretStore: wslvault-backend)
  tenthmatrix/int/config   ──►  ExternalSecret tm-secret-int   ──► Secret tm-secret-int   ──► pod envFrom
  tenthmatrix/test/config  ──►  ExternalSecret tm-secret-test  ──► …                        (Reloader rolls
  tenthmatrix/acc/config   ──►  ExternalSecret tm-secret-acc   ──► …                         pods on change)
  tenthmatrix/prod/config  ──►  ExternalSecret tm-secret-prod  ──► …
```

There is **no kubeseal / SealedSecret path** in `tm-chart` (Workstation still
carries one as a rollback). Nothing secret is committed: no `.env`, no sealed
blobs. `.env.example` is the only template.

## Keys

| Key | Used by | Notes |
|---|---|---|
| `CAPTCHA_SITE_KEY` | lead / comment forms (future captcha) | external value |
| `API_SECRET` | server-side API calls | generate: `openssl rand -hex 32` |
| `JWT_SECRET_KEY` | `scripts/fetchBlogs.mjs` legacy `/all-documents` feed | only when `WEBSITE_NAMESPACE` is unset |
| `BUSINESS_CODE` | OpsAPI business scoping | external value |
| `OPSAPI_URL` | `src/lib/cms.js`, `fetchBlogs.mjs` (server-side) | **in-cluster** URL with trailing `/`, e.g. `http://workstation-opsapi/` — never the public `api.tenthmatrix.com` host |
| `WEBSITE_NAMESPACE` | CMS overlay | must be `tenthmatrix` |
| `OPSAPI_API_KEY` | `scripts/import-blogs-to-cms.mjs --apply`, publish scripts | `cms` scope; never needed by the running site |
| `REVALIDATE_SECRET` *(optional)* | `POST /api/revalidate` HMAC | generated by the seed script if absent; register it as the env's OpsAPI CMS webhook secret |
| `REDIS_URL` *(optional)* | `cache-handler.mjs` | set when an env runs more than one replica |

`OPSAPI_URL`, `WEBSITE_NAMESPACE` and other non-secret settings are **also** set
as plain env in `tm-chart` `appConfig`; explicit `env` wins over `envFrom`, so
the Helm value is authoritative and the Vault copy is a fallback for scripts.

The browser never sees any of these. The lead form's OpsAPI host is derived
from the page host (`src/utils/opsapiEnv.mjs`, checked by `npm run verify:opsapi`).

## What's in this repo

- `helm-charts/tm-chart/templates/externalsecret.yaml` — ExternalSecret, key
  `tenthmatrix/<env>/config`, store `wslvault-backend` (ClusterSecretStore).
- `helm-charts/tm-chart/templates/deployment.yaml` — `envFrom` the Secret
  (`optional: true`, so a not-yet-seeded env still boots on committed JSON) and
  the `reloader.stakater.com/auto` annotation.
- `devops/vault/seed-tm-secrets.sh` — writes one env's path from a local env
  file. **Dry-run by default; `--apply` to write.**

## Provisioning (per env) — needs a Vault token + kubectl

1. **Allow the existing ESO token to read `tenthmatrix/*`.** The
   `wslvault-backend` ClusterSecretStore (applied once per cluster from
   `../workstation-website/devops/vault/wslvault-clustersecretstore.yaml`)
   authenticates with the `wslvault-token` Secret in `external-secrets`. Extend
   that token's policy with read + list on `tenthmatrix/*`, or mint a dedicated
   token and a second store (see *Stronger isolation*).

2. **Write a local env file** outside git (`devops/vault/*.env` is gitignored):
   ```bash
   cp .env.example devops/vault/tm-int.env   # fill in the keys above
   ```

3. **Dry run, then apply:**
   ```bash
   ./devops/vault/seed-tm-secrets.sh int                      # shows keys, writes nothing
   WSLVAULT_TOKEN='<jwt that can write tenthmatrix/*>' \
     ./devops/vault/seed-tm-secrets.sh int --apply
   ```
   An existing path is not overwritten unless you add `--force`. If the script
   generated `REVALIDATE_SECRET`, it prints it: register that value as the env's
   OpsAPI CMS webhook secret for namespace `tenthmatrix`.

4. **Deploy** (`externalSecret.enabled: true` is the chart default). ESO syncs
   `tenthmatrix/<env>/config` into `tm-secret-<env>` and the pod reads it via
   `envFrom`. Do int first.

Requires bash ≥ 4 and `jq` (and `openssl` when generating `REVALIDATE_SECRET`).

## Rotation

Edit the env file and re-run with `--apply --force` (or write via the Vault
UI/CLI). ESO re-syncs within `refreshInterval` (1m) and Reloader rolls the pods.
If you rotate `REVALIDATE_SECRET`, update the OpsAPI webhook secret too.

## Moving off the root path later

Paths are root-level for now. To move under a team prefix, set
`externalSecret.pathPrefix` in `values.yaml` and `PATH_PREFIX` for the seed
script to the same value, seed the new path, then deploy.

## Stronger isolation (optional)

Instead of sharing `wslvault-backend`, create a namespaced `SecretStore` per env
with a token scoped to `tenthmatrix/<env>/*` only, and point
`externalSecret.storeName` / `storeKind: SecretStore` at it in each
`values-<env>.yaml`.
